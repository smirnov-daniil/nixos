---
name: package-herdr-plugin-with-upstream-herdr
description: Bundle a third-party Herdr plugin and track a newer upstream Herdr release inside this flake when nixpkgs is behind.
---

Use `packages/herdr.nix` as the single module for both the wrapped Herdr package and bundled plugins. Fetch the upstream Herdr release source with `pkgs.fetchFromGitHub`, then build the base package with `pkgs.callPackage "${herdrSrc}/nix/package.nix" {}` so you can reuse upstream Nix packaging instead of re-deriving cargo and Zig hashes manually. Fetch the plugin source separately, build its Rust binary with `pkgs.rustPlatform.buildRustPackage`, and assemble a plugin root derivation that contains `herdr-plugin.toml`, `target/release/<plugin-binary>`, helper binaries, and any template files the plugin expects. Wrap the plugin binary with `makeWrapper` if it needs runtime tools like `ssh` on PATH. Wrap Herdr with `inputs.wrappers.lib.wrapPackage`, then expose a final `packages.herdr` via `pkgs.symlinkJoin` that includes both the wrapped Herdr tree and the plugin root. Replace `bin/herdr` with a small shell launcher that runs `${herdrWrapped}/bin/herdr plugin link ${pluginRoot} >/dev/null 2>&1 || true` before `exec`ing Herdr so the plugin is declaratively present for every user session. Verify with `nix build .#herdr`, `nix run .#herdr -- --version`, and a clean `HERDR_SOCKET_PATH=$(mktemp -u)` plus fresh XDG dirs before `nix run .#herdr -- plugin list --json` to avoid protocol mismatches from an older running Herdr server.
